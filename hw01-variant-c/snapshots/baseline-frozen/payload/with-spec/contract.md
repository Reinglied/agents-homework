# Общий раскрытый контракт

Сохраняются run_agent(question, cfg, model_fn, mode="LIVE", emit=print), search_docs/read_doc и синтетический корпус. Разрешено реорганизовать внутренний код. Python 3.11+, стандартная библиотека. Не добавлять shell, исполнение документов, произвольные пути или другие инструменты агента.

1. Неизвестный инструмент, ID, неверный JSON/тип/поля аргументов и исключение инструмента дают структурированный error с code/message. Перехватывать обычные Exception на границе инструмента, не KeyboardInterrupt/SystemExit. Сообщение понятно модели; сырые секреты/трассировки исключений в публичный журнал не попадают.
2. Каждая фактическая попытка вызова модели считается, включая ошибочную. Каждая допущенная к диспетчеризации попытка инструмента считается, включая невалидные аргументы и отказ. Вызовы за пределом бюджета запрещены. Сохраняется политика исходника: пакет, не помещающийся целиком, не исполняется вообще; счётчик инструментов не увеличивается. Ровно помещающийся пакет исполняется. Проверка ответа не расходует инструментальные вызовы; следующее обращение к модели расходует модельный бюджет.
3. При исчерпании бюджета — явный статус и answer=null, без неподтверждённого финального ответа. При ошибке модели — явный статус, сохранённый журнал и точные счётчики, без скрытых повторов. Ошибка инструмента передаётся модели в tool-ответе, исходный вопрос остаётся в истории. Для каждого принятого tool_call сохраняется соответствующий tool_call_id.
4. Журнал содержит попытки модели/инструментов, ошибки/успех, валидацию, реально прочитанные ID и строки и причину завершения. Неуспешное read_doc и сниппет поиска не дают права ссылаться на строки. Счётчики сверяем с фактическими вызовами двойников, не только с журналом самой реализации.
5. Синтаксис ссылки: [D01:1], [D01:1-3], (D01:1), (D01:1-3). Только ASCII-цифры, D и две цифры ID, положительные номера без ведущего нуля, начало <= конец. Поддерживаются обе формы скобок ради совместимости учебного REPLAY. Все строки диапазона должны присутствовать в успешно возвращённых read_doc текущего запуска; номер не равен позиции строки в массиве. Разрыв диапазона не разрешён.
6. Кандидат на ссылку — открывающая скобка [ или (, затем D и две цифры и двоеточие. Некорректный/незакрытый кандидат отклоняется с обратной связью. Просто D01, [D01], (D01), даты (2026-10-20) и обычные скобки — упоминания/текст, не ссылки. Синтаксис сообщается модели заранее.
7. Перед принятием ответа нужен успешный search_docs; при непустой выдаче нужен успешный read_doc и минимум одна корректная ссылка. После успешного пустого поиска допустим ответ об отсутствии сведений без ссылки. Проверка не устанавливает истинность текста: содержательное соответствие, полнота, отсутствие выдуманной цены и выбор редакции оцениваются отдельно.
8. Неверная ссылка не завершает исходную задачу: модель получает точную причину и может исправить ответ в остатке бюджета. Корректные ответы и перефразировки не отклоняются по ключевым словам.
9. Сохраняется поведение домашки: A1 — D01/D02; A2 — отсутствие цены, D03; D05/D01/D06 — актуальная редакция с объяснением; D08 — данные, а не команды. Никаких проверок по ключевым словам как гарантии истинности произвольного текста.
