# Общие проверки для обеих попыток

Из корня проекта:
`python -X utf8 quality/harness.py --agent . --cases quality/public.json --output evidence/logs/public.json`

39 детерминированных сценариев. Двойник модели возвращает заранее заданные сообщения, локальные инструменты реально исполняются, выбранные ошибки/нумерация строк инъецируются на границе run_allowed_tool. Это STUB, не LIVE. Текст корректного ответа подставлен тестом; его принятие не доказывает, что живая модель умеет такой ответ генерировать.

Проверки A1/A2 в STUB подтверждают путь и принятие корректного ответа. Полнота и правильность самостоятельно сгенерированного ответа проверяются отдельно по LIVE-рубрике. A3–A5 воспроизводят ошибки и лимиты управляемо. Внешняя выборка содержит другие данные по тем же раскрытым требованиям, доступна только проверяющему после заморозки обеих первых версий.

Публичный harness и JSON неизменяемы. Собственные дополнительные тесты храните отдельно. Для каждого своего теста укажите требование, режим, ожидание и фактический результат. Сохраните реальный вывод команд. Успехи/провалы относятся к проверяемой версии, не меняйте ожидания для получения PASS.

Внешняя проверка дополнительно вручную оценивает понятность обратной связи (причина и возможность исправить исходную задачу), сохранение разрешённых инструментов и отсутствие исполнения документного текста. Проверка непустого message автоматически не доказывает его полезность.

Доступный OpenSpec CLI: 2.0.0. Для with-spec строгая валидация обязательна до поручения реализации. Direct не создаёт OpenSpec-артефакты. Обоим разрешены одинаковые собственные проверки в рамках общего бюджета.
